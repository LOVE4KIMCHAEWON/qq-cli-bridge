# qq-cli-bridge

A **Chat-only** bridge between the official **Tencent QQ Bot API** and locally installed AI command-line tools.
A QQ message goes in and a text reply comes out, generated by **Claude Code** or a **restricted Codex App Server** on your Windows PC.

> **Not** a remote shell or coding agent. The bridge deliberately disables agent tools (file access, shell, MCP, browser) for QQ traffic.
> Read [Security model](#security-model) before connecting the bot to any group you do not fully trust.

## Features

- **Official QQ Bot transport.** QR-code binding via `@tencent-connect/qqbot-connector` and a WebSocket gateway via `@tencent-connect/qqbot-nodejs`, with reconnect, message de-duplication and access policy.
- **Chat-only AI backends.**
  - Claude Code runs with all built-in tools disabled.
  - Codex runs in a Bridge-enforced restricted App Server mode with hosted web search only.
- **Allowlists.** Separate allowlists for private chat (C2C) users and for groups. In groups the bot answers only when @mentioned.
- **Per-conversation state.** Every QQ conversation (one private chat, or one group) has its own model preference, AI session and long-term memory.
- **Persona.** An editable `persona.md` sets tone and style. It is reloaded without losing history.
- **Long-term Memory.** A SQLite store per conversation, managed from QQ with `/memory`.
- **Culture KB.** A SQLite knowledge base of Chinese internet slang and community norms, learned from explicit corrections.
- **Image search.** Finds existing images with free [DDGS](https://pypi.org/project/ddgs/) (DuckDuckGo) image search via `/image` or natural phrases such as `来张猫猫`. SearXNG, Duitang, Openverse and Pexels are available as opt-in providers. AI image generation is **not** implemented. See [DDGS image search](#ddgs-image-search).
- **Local slash commands.** `/help`, `/model`, `/persona` and `/memory` are handled by the Bridge without spending model tokens.
- **Operational safety.**
  - A single-instance lock.
  - Graceful shutdown that cleans up child processes.
  - Replies have ANSI codes and credential-like strings removed before they reach QQ.
  - An explicit `/approve once` gate for messages that look dangerous.

## Architecture

```
QQ (mobile / desktop)
   │  official QQ Bot WebSocket gateway
   ▼
QqTransport ── dedupe ── accessPolicy (C2C / group allowlists) ── mentionGate (groups)
   │
   ▼
BridgeRuntime
   ├─ local slash-command router (/help /model /persona /memory)    ← no LLM
   ├─ image intent → DDGS search (Python helper) → SSRF-checked download → QQ image
   ├─ approval gate (/approve once | /deny) + turn lock
   ├─ context assembly: Persona → Memory → Culture KB (at session start / rotation)
   ▼
AgentAdapter (Chat-only)
   ├─ Claude Code   oneshot | stream     --tools "" --restricted, empty MCP
   └─ Codex         app-server only      isolated CODEX_HOME, features disabled,
                                         approvals rejected, runtime monitor
   cwd = data/chat-runtime/ (never the repo or your home), scrubbed environment
```

More detail: [ARCHITECTURE.md](./ARCHITECTURE.md), [docs/](./docs).

## Supported backends

| Backend | QQ status | Transport(s) | Notes |
|---------|-----------|--------------|-------|
| **Claude Code** (`claude`) | ✅ **Enabled (recommended)** | `stream` (persistent, recommended) or `oneshot` | Built-in tools disabled with `--tools ""`, `--restricted` and an empty strict MCP config. No web access. |
| **Codex CLI** (`codex`) | ✅ **Enabled, restricted only** | `app-server` | Requires `qqbridge verify-codex-restricted` to pass first. Hosted web search allowed. `oneshot` is refused for QQ. |
| Gemini CLI (`gemini`) | ⛔ Blocked | — | `--approval-mode plan` is read-only, not tool-free. |
| Cursor Agent (`agent`) | ⛔ Blocked | — | No verified no-tools mode. |
| Custom CLIs | ⛔ Blocked | — | Tool disablement cannot be verified. |

The adapters for blocked backends remain in the source tree, but `qqbridge gemini`, `qqbridge agent` and `qqbridge custom` refuse to start under the Chat-only policy.

Versions used during development: Claude Code 2.1.x and Codex CLI 0.169. Newer CLI releases may change flags or feature names. After upgrading Codex, re-run `qqbridge verify-codex-restricted`.

## Requirements

| Requirement | Details |
|-------------|---------|
| **OS** | **Windows 10 / 11** (x64). This is the only tested platform. Linux and macOS are **not supported or tested**: process spawning, lifecycle handling and credential key derivation assume Windows. |
| **Node.js** | **≥ 22.13** (built-in `node:sqlite` without a flag). CI tests Node 22 LTS and 24 LTS. Developed on Node 24. |
| **npm** | Bundled with Node.js. |
| **Git** | To clone the repository. |
| **AI CLI** | At least one of **Claude Code** or **Codex CLI**, installed, on `PATH` and logged in. |
| **QQ** | A QQ account that can own a QQ Bot, and mobile QQ to scan the setup QR code. |
| **Network** | Outbound HTTPS to the QQ Bot API, your AI provider and (optionally) DuckDuckGo for image search. No inbound port is required. |
| **Python** (optional) | Python 3 with the `ddgs` package, only for DDGS image search. See [DDGS image search](#ddgs-image-search). |

## Quick start

```powershell
git clone https://github.com/LOVE4KIMCHAEWON/qq-cli-bridge.git
cd qq-cli-bridge

# Checks Node, runs npm ci + npm run build
powershell -ExecutionPolicy Bypass -File .\scripts\install.ps1

# Put the qqbridge shim on PATH for this terminal (or re-run install.ps1 -AddToUserPath)
$env:Path = "$PWD\bin;" + $env:Path

qqbridge setup                                   # scan the QR code with mobile QQ
qqbridge claude --transport stream --no-terminal # start the bridge
```

Then send a private message to the bot from the QQ account that scanned the QR code.

Manual installation, without the script:

```powershell
npm ci
npm run build
node dist\cli.js --help
```

> `npm install -g .` / `npm link` also work and expose `qqbridge` globally from `dist/cli.js`. The runtime data directory is still `<repo>\data` unless you set `QQBRIDGE_DATA_DIR`.

## QQ Bot registration and setup

1. Make sure your QQ account can own a bot on the [QQ Open Platform](https://q.qq.com/). Follow Tencent's current documentation there if your account has no bot yet.
2. Run:

   ```powershell
   qqbridge setup
   ```

   A QR code appears in the terminal. Scan it with **mobile QQ** and confirm.
   - The official connector returns the bot's **AppID** and **AppSecret**.
   - The Bridge stores both encrypted in `data/secrets/qq.enc.json`.
   - The AppSecret is never printed.
3. If the connector also returns your openid, it is added to the private-chat allowlist automatically. Otherwise:
   - Message the bot once.
   - The bot replies with an "Access denied" message containing your openid.
   - On the PC, run `qqbridge allowlist add <openid>`.
4. Check the result with `qqbridge status`.

For group chat you also have to enable group @-message capability on the QQ Open Platform. See [Private chat, groups and @mentions](#private-chat-groups-and-mentions).

## Claude and Codex prerequisites

The Bridge does **not** install AI CLIs or store their credentials. It launches the CLIs you already use.

**Claude Code**

1. Install Claude Code (see Anthropic's documentation) so that `claude --version` works in PowerShell.
2. Run `claude` once and log in. Alternatively, set `ANTHROPIC_API_KEY` in the environment that starts the Bridge.
3. The Bridge passes only an allowlisted set of auth-related environment variables to the child process.

**Codex CLI**

1. Install the Codex CLI so that `codex --version` works.
2. Run `codex login` in your **normal** Codex home (`%USERPROFILE%\.codex`, or `CODEX_HOME`).
3. Restricted mode creates an **isolated** home at `data/codex-qq-home/`:
   - It **copies `auth.json`** there.
   - It writes its own locked-down `config.toml`.
   - Your plugins, MCP servers and personal config are **not** copied.
4. Run the verification probes. They make three short real model calls.

   ```powershell
   qqbridge verify-codex-restricted
   ```

   On success, the probes write `data/state/codex-restricted-verify.json`. That marker is valid for 7 days and only for the current policy version. The Codex QQ launch **fails closed** without a fresh marker.

## Starting and stopping

```powershell
# Claude (recommended): persistent stream process, fast warm turns
qqbridge claude --transport stream --no-terminal

# Claude one process per turn
qqbridge claude --transport oneshot --no-terminal

# Restricted Codex (after verify-codex-restricted)
qqbridge codex --transport app-server --no-terminal
```

- **Always pass `--no-terminal`.** Chat-only mode never attaches an interactive agent terminal. Without the flag, the command starts and then exits immediately.
- **Always pass `--transport`.** The command-line default (`oneshot`) overwrites the value saved in `config.json`. For Codex this means `--transport app-server` is required every time.
- Only one bridge instance can run per data directory (`data/state/instance.lock`).

Stopping:

- Press **Ctrl+C** in the bridge terminal, or
- run `qqbridge stop` from another terminal. It stops the lock owner, including orphans, and releases the lock.

`qqbridge status` shows the binding, allowlists, lock owner and runtime state.

Run the bridge in the background with Task Scheduler or a service wrapper of your choice. This is not covered by the project.

## Private chat, groups and @mentions

| Setting (`data/config.json`) | Values | Default |
|------------------------------|--------|---------|
| `allowlist.c2cMode` | `allowlist` \| `open` \| `disabled` | `allowlist` |
| `allowlist.users` | user openids | `[]` |
| `allowlist.groupMode` | `allowlist` \| `open` \| `disabled` | `allowlist` |
| `allowlist.groups` | group openids | `[]` |

```powershell
qqbridge allowlist add <user_openid>
qqbridge allowlist add-group <group_openid>
qqbridge allowlist list
```

**Private chat.** Only allowlisted users get AI replies. With an empty allowlist, every sender gets an "Access denied" reply containing their own openid, so the operator can add them.

**Groups.** The group allowlist is **independent** of the user allowlist. Allowing a user does not allow any group.

- With `groupMode: "allowlist"` and an empty list, all group messages are blocked.
- When the bot is added to a group, the Bridge prints the `allowlist add-group` command to run.

**@mentions.** In groups, the bot only responds to messages that @mention it. Mention markers such as `<@…>` are removed before routing, so `@bot /model` works.

**Group memory is shared.** A group is one conversation (`group:<group_openid>`). Every member of an allowlisted group shares that group's AI session, model choice and memory. The allowlist is per group, not per member: anyone in an allowlisted group can talk to the bot.

**Platform settings.** On the QQ Open Platform, enable group @-message capability and add the bot to the group. See [docs/QQ-GROUP-AT.md](./docs/QQ-GROUP-AT.md).

> Setting `c2cMode` or `groupMode` to `open` lets **anyone** use your AI subscription through the bot. Avoid it.

## Persona, Memory and Culture KB

Three separate stores. They are injected once at session start or rotation, in this order: Persona → Memory → Culture. They are not added to every message.

| Store | Purpose | Location | Docs |
|-------|---------|----------|------|
| **Persona** | *How* the assistant talks (tone and style) | `data/persona.md` (UTF-8, created from [examples/persona.example.md](./examples/persona.example.md)) | [docs/PERSONA.md](./docs/PERSONA.md) |
| **Memory** | *What* it remembers per conversation, plus a chat archive | `data/memory/memory.sqlite` | [docs/MEMORY.md](./docs/MEMORY.md) |
| **Culture KB** | Slang and community-norm terms, patterns and corrections | `data/culture/culture.sqlite` | [docs/CULTURE.md](./docs/CULTURE.md) |

- **Persona changes.** Edit `data/persona.md` and send another message. The Claude stream restarts with `--resume --fork-session`, so history is kept. `/persona` shows the file path and hash only, never the text.
- **Memory extraction is rule-based.** It reacts to phrases such as "请记住…", "我喜欢…" or "叫我…", and the Bridge makes no extra model calls for it. Strings that look sensitive (phone numbers, emails, passwords) are skipped.
- **The Memory DB holds a full text archive.** Every QQ turn is stored for each conversation. Treat `data/memory/` as private data.
- **Culture KB seed and learning.** A curated seed is written when the DB is empty. After that, the KB learns from explicit corrections such as `破防的意思是…`. Corrections apply to the current conversation unless the message says 全局 or 永久记住 (global).

## Restricted Codex web search

With the Codex backend, the model can use Codex's **hosted** `web_search` (`web_search = "live"`). The search runs on the provider's side, not as a local command.

- Local shell, `unified_exec`, file changes, MCP, plugins, apps, browser use, computer use, image generation and `view_image` are all disabled.
- `code_mode` / `code_mode_host` must **stay enabled**: on Codex 0.169 the App Server routes hosted search through them.
- **Search results are untrusted input.** Pages can contain prompt-injection text, and the model can repeat false or harmful content.
- Claude Chat-only has **no** web access.

Details: [docs/CODEX-RESTRICTED.md](./docs/CODEX-RESTRICTED.md).

## DDGS image search

Image requests are handled by the Bridge itself, not by the AI backend. The default provider is **DDGS**, a free DuckDuckGo image search through the maintained [`ddgs`](https://pypi.org/project/ddgs/) Python package. It needs no API key.

**Setup**

```powershell
pip install -r requirements-images.txt     # installs ddgs>=9
python scriptsddgs_images.py --query "cat" --max 3   # optional self-test: prints {"ok": true, ...}
```

If `python` on `PATH` is not the interpreter that has `ddgs` installed, set `bridge.images.ddgs.pythonPath` in `data/config.json` or the `QQBRIDGE_DDGS_PYTHON` environment variable.

**Usage from QQ**

- `/image <query>`, for example `/image 猫猫`.
- Natural phrases such as `来张猫猫`; follow-ups such as `再来一张` or `换一张` avoid repeating recently sent images.
- `/image --provider=<id> <query>` pins one provider for a single request.

**How it works**

1. The Bridge runs `scripts/ddgs_images.py` as a one-shot child process (default timeout 12 s) and parses its JSON output.
2. Candidates are filtered by metadata, size and rate limits (`rateLimitPerMinute`, `maxImagesPerRequest`, `minWidth`/`minHeight`).
3. Each image is downloaded with SSRF checks (private, link-local and metadata IPs blocked; redirects re-validated), a size cap and MIME/magic-byte validation, then sent to QQ as an image.

**Configuration** (`data/config.json` → `bridge.images`)

| Key | Default | Meaning |
|-----|---------|---------|
| `enabled` | `true` | Turn image search on or off |
| `providerPriority` | `["ddgs"]` | Ordered providers for ordinary requests. Options: `ddgs`, `searxng`, `duitang`, `openverse`, `pexels` |
| `autoFallback` | `false` | Legacy: append Openverse when earlier providers find nothing |
| `ddgs.enabled` / `ddgs.pythonPath` | `true` / `python` | DDGS provider switch and interpreter |
| `searxng.baseUrl` | `""` | Your own SearXNG instance (skipped when empty) |
| `duitang.enabled` / `duitang.deliveryMode` | `false` / `link` | Duitang provider; `link` sends the source link instead of image bytes |

Notes:

- Results come from the public web and are **not** license-checked or face-verified. Matching is metadata-only; unrelated images are not sent as filler.
- DuckDuckGo may rate-limit heavy use. The Bridge does not bypass CAPTCHAs or rate limits.
- Image search works the same with the Claude and Codex backends, and obeys the same C2C and group allowlists.

More detail: [docs/IMAGES.md](./docs/IMAGES.md).

## QQ commands

Sent as normal QQ messages; in groups, @mention the bot first.

| Command | Effect |
|---------|--------|
| `/help` | List commands (local, no LLM) |
| `/model` | Show the backend, the current model and the available models |
| `/model <model-id>` | Switch the model for **this conversation** |
| `/model default` | Restore the CLI's default model |
| `/persona` | Show the Persona file path and status hash (never the content) |
| `/memory` | List long-term memories for this conversation |
| `/memory forget <id>` | Deactivate one memory |
| `/memory correct <id> <text>` | Replace one memory |
| `/memory clear` | Clear all memories for this conversation |
| `/image <query>` | Search images (DDGS by default) and send them to this chat. `/image --provider=<id> <query>` pins a provider |
| `/approve once` / `/deny` | Answer a pending "dangerous-looking message" confirmation |

Any other message goes to the active AI backend.

- Unknown `/commands` get a hint and are not forwarded.
- Claude has no headless model catalogue, so `/model` lists the documented aliases (`sonnet`, `opus`, …).

## Configuration and data directory

All runtime state lives in **`data/`** next to `package.json`. Override the location with `QQBRIDGE_DATA_DIR`. The directory is created on first run and is **git-ignored**. Never commit it.

```
data/
  config.json                 non-secret settings (template: examples/config.example.json)
  persona.md                  your Persona
  secrets/qq.enc.json         QQ AppID/AppSecret (encrypted at rest)
  secrets/event-hash.key      HMAC key for log content hashes
  codex-qq-home/              isolated Codex home incl. a COPY of your Codex auth.json
  chat-runtime/               empty working directory for AI CLIs
  memory/memory.sqlite        long-term memory + full chat archive
  culture/culture.sqlite      Culture KB
  state/                      sessions, per-conversation models, locks, verify marker
  logs/                       qqbridge.log, usage.jsonl (no prompt text), inbound-events.jsonl
```

See [examples/README.md](./examples/README.md) for the configuration keys.

Environment variables:

| Variable | Purpose |
|----------|---------|
| `QQBRIDGE_DATA_DIR` | Alternate data directory |
| `QQBRIDGE_PERSONA_PATH` | Alternate Persona file (advanced / tests) |
| `QQBRIDGE_DDGS_PYTHON` | Python executable for DDGS image search (falls back to `PYTHON`, then `python`) |
| `SEARXNG_BASE_URL` | Your own SearXNG instance for the optional `searxng` image provider |
| `OPENVERSE_CLIENT_ID`, `OPENVERSE_CLIENT_SECRET` | Optional Openverse API credentials (higher rate limits) |
| `PEXELS_API_KEY` | Optional Pexels API key for the `pexels` image provider |

The Bridge does not load `.env` files. Set variables in the shell, user environment or service wrapper that starts it.

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| `QQ is not configured. Run: qqbridge setup` | Run `qqbridge setup`. If you moved `data/`, renamed the PC or changed Windows user, the credential key changed: run setup again. |
| `Command not found: claude` / `codex` | Install the CLI and ensure it is on `PATH` in the same terminal, or set `agents.<name>.command` in `data/config.json` to a full path. |
| Bridge exits right after starting | Add `--no-terminal`. |
| `Codex QQ requires restricted App Server mode` | Use `qqbridge codex --transport app-server --no-terminal`. |
| `verify marker missing/stale` | Run `qqbridge verify-codex-restricted` (again after Codex upgrades or after 7 days). |
| Verify fails on `web_search` | Make sure `codex login` works and your plan includes web search. Do not disable `code_mode_host`. |
| Private messages get "Access denied" | `qqbridge allowlist add <openid>` using the openid shown in the reply. |
| No reply in a group | The group must be allowlisted, the message must @mention the bot, and group @-messages must be enabled on the QQ Open Platform. Check `data/logs/qqbridge.log` for `filtered_access_policy` / `filtered_mention_gate`. |
| `Another qqbridge instance is already running` | `qqbridge stop`, or check `qqbridge status` for the lock owner. |
| `ExperimentalWarning: SQLite is an experimental feature` | Harmless; printed by Node for `node:sqlite`. |
| Chinese text garbled in Windows PowerShell 5.1 | Display only. Use Windows Terminal / PowerShell 7, or `chcp 65001`. Files are UTF-8. |
| `/model` cannot list models | Claude has no headless catalogue (aliases only). For Codex, check that `codex` works. |

Logs: `data/logs/qqbridge.log`.

## Security model

Summary only. Read [SECURITY.md](./SECURITY.md) and [docs/CHAT-ONLY-SECURITY.md](./docs/CHAT-ONLY-SECURITY.md) for the full model.

- **Claude Chat-only disables model tools.**
  - Flags: `--tools ""`, `--restricted`, `--strict-mcp-config` with an empty MCP config, and `--permission-mode dontAsk`.
  - The working directory is the empty `data/chat-runtime/`.
  - The child environment is scrubbed.
  - Dangerous `extraArgs` (`--yolo`, `--dangerously-*`, `--add-dir`, `--mcp-config`, …) are stripped.
- **Restricted Codex uses several layers.**
  - An isolated configuration with feature flags that disable local tools.
  - A `read-only` sandbox setting, with the Bridge rejecting **every** approval request.
  - A runtime monitor that fails the turn if a forbidden tool item appears.
  - Startup verification probes.
  - **Codex is not OS-sandboxed:** Windows AppContainer isolation is not available in the tested Codex build. The model may still *see* some tool schemas.
- **Hosted web search returns untrusted content** that can carry prompt injection.
- **Access control is enforced by the Bridge.** It applies the allowlists, @mention gating and per-conversation separation of sessions, model choices and memory.
  - These are application-level controls, not OS isolation.
  - The Bridge process can read all conversations' data.
- **Credential encryption is obfuscation.** QQ credentials are AES-256-GCM encrypted with a key derived from the computer name, Windows user name and data path. This stops casual disclosure, but **not** someone who can read your files as your user.
- **This project does not provide guaranteed isolation.** Don't add the bot to untrusted groups and don't use `open` modes unless you accept that strangers can drive your AI account and see replies built from shared group context.
- **Never commit** `data/`, `auth.json`, `*.enc.json`, SQLite databases, logs or your Persona.

## Development and testing

```powershell
npm ci
npm run build          # tsc → dist/
npm test               # offline suite; isolated temp QQBRIDGE_DATA_DIR
npm run dev -- status  # run from source via tsx
```

- **`npm test`** needs no QQ credentials, AI CLIs or network. It always uses a temporary data directory, so it never touches your real `data/`.
- **`npm run test:live`** additionally runs live tests. These call your **real, logged-in** Claude, Cursor Agent and Codex CLIs and consume usage. Gates: `QQBRIDGE_LIVE_TESTS=1` and `QQBRIDGE_CODEX_LIVE_VERIFY=1`.
- **Manual end-to-end QQ checklist:** [TESTING.md](./TESTING.md).
- **`scripts/` and `tools/`** contain developer benchmarks and probes that require authenticated CLIs. They are not part of the bridge.
- **CI** (GitHub Actions, Windows, Node 22 and 24) runs `npm ci`, the build, the offline tests and a CLI smoke test.
